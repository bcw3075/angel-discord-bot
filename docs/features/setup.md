Settings, keys and the owner's own files; the setup and check scripts; the logger; building the services; starting.

## Decisions
- **`npm run check` lists each table** (0.2.0): its server, channels, game and answers switch, then that table's files; it moves the files of before 0.2.0 into their table as the bot's start does. `Test Angel.cmd` and `npm run ask` answer with the one answering table's house rules and say which, or stop and say why when there isn't exactly one.
- **The busy table's settings** (0.1.3, `config.mjs`): `busyTable` (true), `busyBlipMs` (500), `busyPauseMs` (800), `busyFirstWaitMs` (2000), `busyGapMs` (1500), `busyMaxHoldMs` (60000), each with a floor below which the default is used and named. The self-test has a step for the check while she waits (`holdKind`, with the case's `waiting`) and one for her "I'm ready" words (`ready`): Rhea's d-7 asked for self-test cases for the go-ahead, hold-on, stop and new-question judging.
- **`Test Angel.cmd`: a break-it suite with the owner's own keys** (Rhea, 2026-11-14, after two failed live rounds: "Would there be a way for you to get a test api just for testing?", then "you should come up with a whole bunch of tests to use with it" and "Think of every different possible way to break it"). A key in the build workspace would have to pass through the chat, so the test runs on her PC instead: `check.mjs --selftest` puts 69 cases (`CASES` in `selftest.mjs`; nine for asking for more detail, not understanding, pushing back and questions too vague to answer; 31 added the same evening at her word, "Do you want to come up with more questions while we are at it?") through the real check and the real answering, three at a time, without Discord: rules of every kind, old names, two printings of one name, exact numbers, several questions in one, a player who is wrong, a rule that doesn't exist, a GM's call, "that" from the conversation, garbled and odd words, a very long question, typed, attempts to talk her out of her rules, small talk, and lines that are not for her. Each step notes the check's verdict, the times, rounds and lookups, both answers and the pages, and marks "look at" when a pattern for the right answer misses; the report is `data/selftest/selftest-<time>.md`. The patterns are a first sieve: Angel reads every answer against Archives of Nethys. Her hearing and her voice are not part of it. A run costs about a dollar and is not counted against the daily cap.
- **Prices and floors are checked** (full code check, 2026-11-14): a price that isn't a number ("$2") made every total "not a number", which broke the caps; such an entry is replaced by the built-in price (or dropped, so the dearest known price counts) and named in the problems list. The caps, `memoryMinutes`, `maxAnswerTokens`, `silenceMs`, `maxUtteranceSeconds`, `replyWindowMs` and `followUpMs` below their floor fall back to the default, also named.
- Runs on the owner's Windows PC beside her other tools, started by `Start Angel.cmd` with a restart loop (the bridge's pattern). It only connects out, so no tunnel or port. (Angel's choice, 2026-11-12, in the design.)
- Its own Claude Console workspace and key with a monthly cap, separate from other API spend. (Angel's choice, 2026-11-12.)
- Keys are pasted into `npm run setup` without echo and live only in `config.json`; the logger blanks them out of every line. Nothing prints them whole: setup shows only `pasteSummary`, on screen, never in the log.
- The table's own files (`house-rules.md`, `keyterms.txt`, `speakers.json`) sit beside the code and are git-ignored: the repo is public and holds no campaign content.
- Models: Sonnet 5.5 answers, Haiku 5.5 checks wake words (the owner chose Sonnet by default for her other API work, 2026-11-12). One setting each in `config.json`.
- **What setup writes** (third review, 2026-11-13): the keys and every setting she might change, so she can see them in Notepad, but not the models, prices or AoN user agent (`FOLLOW_RELEASES`) unless they differ from the defaults. Saved values win over the code's, and an update keeps `config.json`, so writing those would have frozen them at the first install: a retired model would break every answer until she edited the file by hand.
- **What she sees after a paste** (Rhea asked to see the key while pasting, 2026-11-14): not the key, since she sends screenshots of that window to Angel, but `pasteSummary`: its first characters (a quarter at most, 12 at most), the last 4 and the length, so she can check it against the site; a key under 16 characters shows only its length. For a Claude key that's `sk-ant-api03` and the 4 the Console's list shows anyway; a Discord token's start is its public bot id; a 40-character Deepgram key shows 14, leaving 104 bits hidden. A kept key (Enter at a question) answers `Kept:` the same way.
- **A key that looks wrong is not saved** (Rhea, 2026-11-14: she pasted a token without Enter, reset it, pasted the new one, and both were saved as one): setup asks again; Enter keeps the old key; the same odd-looking key pasted twice in a row is saved, so a key format the check doesn't know can't lock her out.
- **`Install Angel.cmd`** (Rhea: "as easy or automated for me", 2026-11-14): one double-click runs the Node check, `npm install`, setup, a pause for the invite link, setup again for the server, and `npm run check`. Angel's computer use can't type in a terminal, so a script she starts is the way to spare her the typing.
- Command Prompt, not PowerShell, for every install step: on a default Windows 11, PowerShell refuses `npm.ps1` (scripts disabled), a widely reported trap. The README says so at step 2.

## How it works
- `withNames` (`src/services.mjs`) adds the names of the people heard this session to `keyterms.txt`'s terms for each piece sent to the transcriber: the file's terms first, no repeats (case ignored), names of at most 40 characters with a letter, within Deepgram's 100 (live round 2026-11-16).
- `config.mjs`: `DEFAULTS` merged under `config.json` (prices merge per model). A setting keeps its default's kind (`"false"` with quote marks is false, `"$5"` is 5); one that can't be read that way gets the default and a line in `cfg.problems` (not enumerable, so never saved), which `npm run check` shows as a FAIL and `main` logs as a warning. Before this, a cap typed as `"$10"` stayed text and never tripped (fourth review). A `guildId` without quote marks is a problem too: JSON rounds an 18 or 19 digit number. So is an answer or check model with no price. `readKeyterms` always puts "Angel" first and caps the list at 100. `readText` reads every file the way Notepad may save it: UTF-8 with or without a byte-order mark, "Unicode" (UTF-16 LE) or "Unicode big endian". `tableFilesReport` tells `npm run check` what it found of the table's files, and fails a `house-rules.md.txt` or `keyterms.txt.txt` (extensions hidden in File Explorer) or a broken `speakers.json`. `fixFor` adds what to do to a FAIL line: a refused key or no credit only for Claude and Deepgram (Archives of Nethys has no key, and a JSON error's "position 402" isn't a status), a refused Discord token, and no connection or a time-out for any; `keyLooksWrong` catches at setup a key pasted twice (its two halves the same), two different keys on one line, or one pasted into the wrong question; `askKey` (setup.mjs) then asks again instead of saving it.
- `services.mjs` builds the shared wiring once (Claude, AoN with its cache file, Deepgram listening and voice, the gate, the answering); `main.mjs` and `check.mjs` both use it. House rules are read for each question, so an edit counts without a restart.
- `main.mjs` exits 2 for "needs setup" (missing keys, a refused token, a `config.json` that can't be read) so `Start Angel.cmd` stops with a message instead of restarting every 10 seconds; other failures exit 1 and restart. Ctrl+C, closing the window (SIGHUP, and SIGBREAK for Ctrl+Break on Windows) and SIGTERM book the day's spending at once, end sessions within 4 seconds (Windows gives a closing window only a few) and save the AoN cache, then exit 3, which `Start Angel.cmd` takes as "stopped on purpose" and ends; a second signal books and quits at once. A crash books the live sessions' spending and saves the cache before exiting 1.
- `Start Angel.cmd` first checks that `node` is found and that `node_modules` holds the packages, and otherwise says what to do and stops (before, a missing Node or a run before `npm install`, or from inside the zip, restarted every 10 seconds forever). In the loop it stops with a message on exit 2, ends on exit 3, and restarts on anything else. It waits with `ping`, not `timeout`, which fails at once without a console window (Task Scheduler's "run whether logged on or not") and would make a fast restart loop (review L13). Pure ASCII with CRLF line ends (`.gitattributes`).
- `check.mjs --voices` saves a sample of each voice as an mp3 named after it in the data voices folder and marks the current one; `--set <name>` saves `ttsVoice` in `config.json` (the keys are rewritten unchanged by `saveConfig`). `Choose Voice.cmd` runs both and opens the folder.
- `check.mjs` runs on the owner's PC: the table's files, both Claude models, Deepgram voice (WAV saved to hear, Ogg Opus read back packet by packet and decoded), Deepgram listening of that same WAV, AoN, Discord and the Message Content intent (with a 30-second limit, so a blocked connection can't hang it). `--voices` saves samples; `--ask` runs one real answer without Discord and shows the prompt cache's tokens written and read.
- `Install Angel.cmd`: Node found and 22.12 or newer (otherwise opens nodejs.org and stops), after checking it runs beside `package.json` (not from inside the zip), then the four steps (the invite step and its second setup round skipped when `config.json` already names the server: Rhea found asking the keys twice "very confusing", 2026-11-14), stopping with "tell Angel" on a failed step. Setup exits 1 when there's no Discord token or Discord refused or didn't answer, so the installer stops before pointing at an invite link it never got; `npm run check` exits 1 on any FAIL. Pure ASCII with CRLF like the start file.
- `setup.mjs` prints `Got it: <pasteSummary>` after each key; it stops with the plain message on a `config.json` it can't read; Ctrl+C at a question stops it without saving; a window that isn't a terminal (Git Bash's) gets a warning that pasted keys may show. Its Discord check has a 30-second limit (`within`), and only blames the token when Discord refused it (`tokenRefused`); anything else says the keys are saved and to check the connection. It exports `inviteUrl` and `INVITE_PERMISSIONS` (View Channel, Send Messages, Embed Links, Read Message History, Add Reactions, Connect, Speak, Use Voice Activity, Create Public Threads, Send Messages in Threads); it only runs its prompts when started as `src/setup.mjs`.

## Traps
- A rules fact written into a self-test pattern from memory was wrong: "resistance to all damage applies to each type" is the old rule; Player Core's Resistance on Archives of Nethys now says it is used once, against one type the target chooses (read 2026-11-14). Every fact in `CASES` is read from the real entry before it goes in.
- `npm install prism-media` as a direct dependency fails: prism-media 1.3.5 wants `opusscript ^0.0.8` as a peer and this package uses 0.1.1. Don't add it; `tts.mjs` has its own small Ogg reader for the checks, and playback uses the copy inside @discordjs/voice.
- A time limit's timer must not be `unref`'d when it guards a step that may be the only thing running: a hung login would then end the process silently instead of with the reason (caught by its own test, 2026-11-13).
- On Node 22, `node --test test/` treats the folder as a file; the test script uses the quoted glob `"test/*.test.mjs"`.
