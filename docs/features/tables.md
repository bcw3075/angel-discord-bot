One folder per game table (server, channels, game, the answers switch, its own house rules, key terms and speakers), picked by where `/angel join` is typed; a table where she only listens.

## Decisions
- **Angel is for more than one table** (the owner, 2026-11-21): one core Angel, a folder per table, and nothing crossing between folders, so one table's rulings, names and transcripts never reach another. Real table folders are campaign content: they live beside the code on the owner's PC (`tables/<name>/`, git-ignored) and never in this repo. `examples/tables/example-table/` is made up.
- **The table is picked by where `/angel join` is typed** (Angel's proposal, the owner can overrule): the table that names that channel, else the one table on that server, else, of several on that server, the one that names no channels. No match, or two tables that both could be meant: she says so and doesn't join. There is no setting or command to choose a table by hand, so a table's rulings can't be loaded at the wrong one.
- **The voice channel can't belong to another table** (review 1): `/angel join` typed in one table's channel while the caller sits in a voice channel another table names is refused, so one table's game is never heard as another's. A listen-only table that shares a server should name its voice channel too.
- **A thread counts only as its parent channel** (review 1): its own name is anyone's to choose, so a thread named like another table's channel never picks that table. A thread is told by its type, not by having a parent: every channel in a category has the category as its parent (review 2). A channel that can't be looked up, where tables share a server, picks none.
- **A live session keeps the table it joined with** (review 1): a `table.json` edit counts at the next join; until then typed questions in the session's table are handled as at the join, so its voice and typed sides never differ.
- **Served by id only; a name is turned into the id once** (review 4 replaced three rounds of patches to name matching): anyone who can invite her (a Public Bot, needed so another table's GM can invite her) could make a server of the same name, so a table serves a server only by its id. A `table.json` may name its server by name until the id is known: the first time exactly one server she is in has that name (at start, or when she is invited), its id is written into that `table.json`, the other settings kept, and from then on only that server is the table's. Two servers of that name: nothing is written and the log lists their ids. So the owner writes a name and never has to find an id. What is left (review 5): the first server of that name she is invited to wins, so an impostor would have to invite her before the real one; keep the Discord app's Public Bot switch on only while another table's GM invites her, and check the log's "written into its table.json" line names the right server. Nothing is pinned while a server she is in is unavailable (it has no name then), and the write is whole-file-then-swap.
- **`/angel leave`, `stop` and `status` act only from the session's own table** (review 3): there is one session per server, and from another table's channel she says which table she is listening for instead of ending, hushing or reporting it. From a channel with no table, or when the session's table has gone (renamed during the session), they still work, so a session can always be ended (review 4).
- **A per-table answers switch** (the owner, 2026-11-21, passing on another table's GM's wish: "only listen so we can build summaries and campaign details after"). Off: she joins, says once in writing that she is listening and transcribing (and that `/angel optout` makes her ignore a voice), keeps the transcript, and never speaks. No "was that for me?" check, no lookups, no quick reactions, no busy-table watch: the only cost is listening. A typed `@Angel`, "Angel, ..." or `/angel ask` gets one short line saying she only listens at this table (and is kept in the transcript). The note after a rejoin is written only. `join`, `leave`, `optout`, `iam` and `status` work as everywhere.
- **Fail closed** (Angel's choice): a `table.json` that can't be read, or names no server, leaves its table out (she then joins nowhere it would have served); an answers switch that can't be read, or isn't set, means listen only. A mistake never makes her speak where she shouldn't.
- **Answering needs Pathfinder 2e** for now: Archives of Nethys is her only rules source. `game` must name the second edition (`pf2e`, `PF 2e`, `Pathfinder 2e`, `Pathfinder 2nd Edition`, `Pathfinder Second Edition`, with or without "Remaster"); a plain "Pathfinder" could be first edition (review 3). A table with `"answers": true` and another game is listened to only, with a line in the log and in `npm run check`.
- **Spending caps count every table together** (unchanged): the session cap is per session, the daily cap is one total for the day.
- **`/angel optout` stays one list for every table** (Angel's choice): it is a person's wish not to be transcribed, not a table's ruling, and the safer reading is "nowhere".
- **The files of before 0.2.0 move by themselves** (the owner: "her PC's files moved by the update without her doing anything"): at start, and at `npm run check`, `house-rules.md`, `keyterms.txt` and `speakers.json` beside the code move into the table serving `guildId` (the server they were used on), or else the one table that answers (before 0.2.0 every table answered). A file the table already has is removed when identical and kept as `<name>.old` (`.old2` and on, never over an earlier one) when it differs. With no `tables/` folder she works exactly as before 0.2.0 (the files beside the code, `guildId`), so a fresh install needs no table.
- **`guildId` isn't used once there are tables**: each `table.json` names its server, and `/angel` is registered on every server a table names (and on a server she is invited to while running, if a table names it).
- **Not in 0.2.0**: a rules part of her instructions per table (only Pathfinder answers so far), banter and chiming-in switches (those features aren't built), summaries from a transcript.

## How it works
- `tables/<name>/table.json`: `server` (id in quote marks, or the exact server name until `pinServers` writes the id in), `channels` (optional list of ids or names, `#` optional, any case; a thread counts as its parent channel), `game`, `answers` (true/false), `transcriptKeptBy` (optional: whose computer the notice names; default "the GM's"). Beside it: `house-rules.md`, `keyterms.txt`, `speakers.json`, read with the same readers as before.
- `loadTables` reads every folder each time it is asked (a `table.json` edit counts without a restart); `pickTable` picks; `moveOldFiles` moves the old files once; `answeringTable` picks the table `Test Angel.cmd` and `npm run ask` use (exactly one answering table, or it says why not).
- The bot keeps one session per server, now with its table. Typed messages go to the session only when they are in that session's table; a question typed in another table's channel on the same server is answered (or not) as that table, without the session's conversation.
- The session's speaker names, key terms (`services.keytermsOf`), house rules (`services.answer({ table })`) and transcript folder (`data/sessions/<table>/<date>/`) all come from its table. The legacy single table keeps `data/sessions/<date>/`.
- `Session({ listenOnly: true })`: `hearPiece` goes to `hearOnly` (transcribe, write the line, nothing else); `start` makes no "checking" clip and no floor; `textQuestion` replies `LISTEN_ONLY_REPLY`; `rejoined` writes only; the summary leaves out questions.

## Traps
- **Every channel in a category has a `parentId`** (the category's), so `parentId` doesn't mean "thread": review 2 found the first thread fix matching every categorised channel by its category. Tell a thread by `isThread()` or its type (10, 11, 12), and test with a categorised channel as well as a thread.
- **A server name was matched for three review rounds**, each fix leaving the next hole (a namesake server on restart, on invite, two of a name): replaced by one rule, served by id only, a name turned into the id once.
- A server id written without quote marks in `table.json` loses its last digits (JSON numbers): such a table is left out with a line saying so, as `guildId` was.
