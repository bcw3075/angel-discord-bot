First review (a fresh agent; it read the diff, the five changed source files, the session and answering docs and the code rules; it ran the tests 48 times six at a time and fuzzed the readers with 20,000 random inputs each). No high finding. Each finding was checked against the code:

Tests: the session's "her last sentence, or her only one" and the answering test's end signal; each fails with its fix removed.
- M2 true, fixed: no test proved the reply is read as it arrives. The answering test now sees her first words passed on with most of the reply still to come.
- L1 true, fixed: a reply that breaks off before its end carries no count of what was written, so that part cost nothing in the tally. Now a token per three characters received. The usage of an attempt that was overloaded before anything was written is still not counted (not fixed: nothing was written, and the next attempt's usage is).
- L2 true, fixed: a `say` holding only spaces was never spoken although the transcript had her apology. The fallback now goes by what was handed to the voice.
- L3 true, fixed: the cut-short fallback looked its reader up by the wrong index when blocks were skipped. There is only one reader: it is used.
- L4 true, fixed: an error while handing a sentence over is logged.
- L5 true, fixed: a throw from the voice's speak is caught where it happens (the real one can't throw; hardening).
- L6 true, fixed: a long run of end marks arriving one at a time was read again at each piece (8,000 took 0.4 s). The cutter remembers how far it read; the timing test now feeds 30,000 one at a time.
- L7 true, fixed in part: tests added for no voice being made after a stop, a session ending mid-answer, the time limit passing while the reply is read, and Windows line ends. Not added: the stop and end checks on her quick reaction's fallback clip.
