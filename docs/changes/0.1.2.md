## Review
<!-- The independent reviewer's findings, each marked verified true or false and what was done.
     Required when code changed; otherwise write `waived by Rhea <date>` with her reason. -->
First review (a fresh agent; it read the diff, the five changed source files, the session and answering docs and the code rules; it ran the tests 48 times six at a time and fuzzed the readers with 20,000 random inputs each). No high finding. Each finding was checked against the code:
- M1 true, fixed: a one-sentence `say`, and the last sentence of every `say`, waited for the whole answer (the cutter needs the space after a sentence, and nothing follows the last). `answerQuestion` now signals the end of `say` and the session speaks what is left then. Tests: the session's "her last sentence, or her only one" and the answering test's end signal; each fails with its fix removed.
- M2 true, fixed: no test proved the reply is read as it arrives. The answering test now sees her first words passed on with most of the reply still to come.
- L1 true, fixed: a reply that breaks off before its end carries no count of what was written, so that part cost nothing in the tally. Now a token per three characters received. The usage of an attempt that was overloaded before anything was written is still not counted (not fixed: nothing was written, and the next attempt's usage is).
- L2 true, fixed: a `say` holding only spaces was never spoken although the transcript had her apology. The fallback now goes by what was handed to the voice.
- L3 true, fixed: the cut-short fallback looked its reader up by the wrong index when blocks were skipped. There is only one reader: it is used.
- L4 true, fixed: an error while handing a sentence over is logged.
- L5 true, fixed: a throw from the voice's speak is caught where it happens (the real one can't throw; hardening).
- L6 true, fixed: a long run of end marks arriving one at a time was read again at each piece (8,000 took 0.4 s). The cutter remembers how far it read; the timing test now feeds 30,000 one at a time.
- L7 true, fixed in part: tests added for no voice being made after a stop, a session ending mid-answer, the time limit passing while the reply is read, and Windows line ends. Not added: the stop and end checks on her quick reaction's fallback clip.
- L8: the small-talk change is now in the session doc. The transcript-order point is false: `Transcript.add` puts a line in by its time, and the file is written again in order when the session ends. The spoken copy having spaces where the parsed `say` has line breaks is harmless, as the reviewer says.
- Its "not checked" list: `tts.mjs` has a 30 s limit on each voice request (read: `synthesize`'s `timeoutMs`), so a hung request can't block the queue for longer than that.

Second review (another fresh agent, on the code after the first round's fixes; it fuzzed the sentence cutter with 200,000 random texts and found nothing lost or doubled). Each finding checked against the code:
- 1 true, fixed: the first round's cost estimate for a broken reply never ran against the real API, because the start event already carries `output_tokens` (a placeholder of 1) and the test's stand-in left it out. The estimate now runs whenever the end-of-reply count never came, and the stand-in's start event has the placeholder. The test fails with the old condition.
- 2 true, fixed: a reply that broke off after she had said all of her spoken answer (while the written part was being written) made her add "Sorry, I couldn't reach my rules brain" on top of a complete answer, and posted only the apology. Now what she said is the answer and the post says the written details were lost. New test.
- 3 not changed: after a stop mid-answer the transcript and the echo check hold her whole answer though only part was heard. It was the same in 0.1.1 for an answer stopped before it was spoken (the answer is still typed in the channel, and the transcript is what she is given as the conversation); left as it was.
- 4 false for the finished file: the transcript file is appended as lines arrive and written again in time order when the session ends (`Transcript.close`); mid-session her line can sit a few lines late, as any late-transcribed line can.
- The second round's two fixes get their own fresh review before the final gate, together with anything the live test changes (pending).
- Seen while testing, not from this change: the old speed test in `test/wake.test.mjs` (50 ms per odd text) fails when six or eight test runs go at once in this workspace; alone it passes.
