Independent reviewer (fresh agent, 2026-11-13 00:17 to 00:31; read all of src/, the feature docs, DEVELOPING.md, README, package.json, .modtools.json, Start Angel.cmd; grepped the library typings; ran the tests and probes). No crash path and no runaway-spend loop found. Each finding was checked against the code (and, for M1, M3, M4, L1 and L10, by running the code) before fixing:
- M1 verified true: the gate's fallback read "Mira: Angel, ..." and never matched, so a failed check lost every spoken question, silently. Fixed: `bareText` for the fallback, the failure logged; tests in wake and session.
- M2 verified true: "Angel, stop" didn't cancel an answer still being looked up or questions queued behind it. Fixed: a stop count stamped on each question; dropped if stopped before its turn (a typed one is told), typed but not spoken if stopped during the lookup; test. (The count was replaced by stop times in the second review, S2.)
- M3 verified true: the stop shortcut matched anywhere ("Angel, never mind that, how does flanking work?", "the angel, quiet as death"). Fixed: her name first and at most three words after the stop word; a gate stop with a real question stops and then answers; tests.
- M4 verified true: a typed "Angel, stop" became a paid question. Fixed: typed stop phrases stop her; test.
- M5 verified true, all four parts: no cap outside a session, `guildId` only limited registration, queued answers ran past the cap, a failed answer's cost was lost, `/angel ask` past the cap hung. Fixed: a daily cap (`maxDailyDollars`, `data/spend.json`) over everything, `serves()` limits commands and messages to `guildId`, the cap checked in `runAsk` and before the voice, `dollars` on the error, a reply past the cap; tests.
- M6 verified true: a line said while the check ran was dropped. Fixed: `checking` keeps it as the rest of the question; test.
- M7 verified true: a typo in `speakers.json` was read as empty and the next `/angel iam` wiped it. Fixed: a strict read before writing (refuses and says so), a warning otherwise; tests.
- M8 verified true: two quick `/angel join` made two sessions. Fixed: `joining` marked before the first await; test.
- L1 true: typed "Angel wings ..." was a question. Fixed: a comma, colon or question mark after the name, or "hey Angel"; test.
- L2 true: a broken `config.json` restart-looped; Ctrl+C could hang. Fixed: exit 2 for it; a 5-second shutdown limit and a second Ctrl+C quits.
- L3 true: a reconnect stuck before Ready, or a destroyed connection, wasn't noticed. Fixed: 20 s for Ready, Destroyed watched; test. (The 20 s wait rarely ran; replaced by a watchdog in the second review, S11.)
- L4 true (sizes not measured): full texts cached and the file rewritten at each miss. Fixed: texts cut before caching, 200 entries, saved a few seconds after the last lookup and at shutdown; test. No backoff on AoN's 429: left as is (a failed lookup is told to Claude, and a question makes at most a few requests).
- L5 true: the key-term price was only counted with more than one term, but "Angel" is always sent. Fixed.
- L6 true: `transcript.md` was in arrival order. Fixed: rewritten in time order at the end; test.
- L7 true for frames over 20 ms (a RangeError). Fixed: frames of any length decode whole; checked with real 40 ms and 60 ms frames from ffmpeg; test with a 40 ms fixture.
- L8 true: a 90 s limit with retries could hold the queue for minutes, and a timed-out call may be billed. Fixed: 45 s, no retry after a timeout; test.
- L9 true: slash-command replies set no allowedMentions. Fixed: no pings on every reply and edit; test.

Second independent reviewer (fresh agent, 2026-11-13, after the first round of fixes; read the code and the touched feature docs, ran probes). Each finding was checked against the code before fixing (S1 by timing it, S11 and S12 by reading the installed library):
- S1 (high) verified true: the stop pattern could match "her name, anything, a stop word" in very many ways; a 60-word line took 1.3 s, and the whole bot waits while a regex runs. Fixed: matched only at the start, the words after it counted in plain code, at most 120 characters; the gate's fallback reads the first 300 characters. Now under 1 ms; a timing test runs every text reader (the stop and name checks, the fallback, `typedQuestion`, `speakable`) on 4,000 characters of odd text.
- S2 verified true: with stops counted, a stop said while the check on a question ran came before the question was stamped, so it didn't cover it. Fixed: stops by time (`stop(at)`, `stoppedSince(at)`), checked when the check returns and when the question's turn comes; tests for a finished and an unfinished question.
- S3 verified true: what the speaker added while the check ran was dropped when the check called the question finished. Fixed: always added; test.
- S4 verified true: a typed question queued when the session ended got no reply, so a deferred `/angel ask` showed "thinking" until Discord gave up. Fixed: "The session ended before I got to ..."; test.
- S5 verified true: a live session's spending was only in memory, so a crash or a closed window reset the daily cap. Fixed: running totals written every minute and counted at the next start, an answer finishing after the end booked, a crash books before exiting, and closing the window (SIGHUP, SIGBREAK) ends sessions cleanly; tests for the first two.
- S6 verified true: Discord nicknames weren't cleaned like `/angel iam` names, so "Sam (GM)" could make a GM line. Fixed: `cleanName` in `speakerOf`; test.
- S7 verified true: `guildId` written as a number never matched, and a wrong one registered `/angel` nowhere without a word. Fixed: compared as text, a warning at start; test.
- S8 verified true: the voice join came before finding the text channel, so a channel she can't post in left a voice connection open. Fixed: the channel first; test.
- S9 verified true: a typed "@Angel stop" was a paid question. Fixed: the mention read as "Angel" for the stop check; test.
- S10 verified true: an AoN text cut before caching could look whole once its spaces were collapsed, so Claude wasn't told it was cut. Fixed: `_cut` marks it; test.
- S11 verified true by reading @discordjs/voice 0.19.2: most reconnects go from Ready straight to Signalling and never pass Disconnected, so the L3 wait rarely ran, and an `error` event during that wait counted as lost. Fixed: a watchdog on every state change (back to Ready within 30 s, else lost), and only the 5 s timeout counts in the Disconnected handler; test.
- S12 verified true: my L10 line above was wrong (corrected there).
- S13 verified true: a comment in `audio.mjs` said only 20 ms frames decode. Fixed: the comment.
Each new test was checked by breaking its fix and seeing it fail; two passed at first (one because a later guard caught the same case, one because its stand-in check never answered) and were corrected. After the fixes: 100 tests pass, the lint is clean.

- [module] Discord has required DAVE end-to-end voice encryption from every client, bots included, since 2 March 2026; @discordjs/voice receives encrypted audio from 0.19.2 (the fix for discord.js issue 11419). → filed: docs/features/voice.md
- [module] @discordjs/voice destroys a speaker's stream with an error on a packet it can't parse, and marks speaking ended 100 ms after the last packet: handle every stream error (`on`, not `once`) and listen again when a stream closes while the speaker is still marked speaking. → filed: docs/features/voice.md
- [module] prism-media can't be a direct dependency beside opusscript 0.1.1 (its opusscript peer range is ^0.0.8); `node --test test/` doesn't take a folder on Node 22. → filed: docs/features/setup.md
- [module] The AoN search index refuses `_mapping` to anonymous users; `url` and `category` take `term`, `id` doesn't (use `ids` on `_id`); old entries point to Remaster ones with `remaster_id`. → filed: docs/features/answering.md
- [module] A one-off lint for undefined names found a crash in the Discord handlers that no test reached; the handlers now have stand-in tests. → filed: docs/DEVELOPING.md
- [module] The independent review found 8 medium and 15 low problems that the 66 stand-in tests didn't (the gate's fallback, stop, caps, a race); each is now a test, and the traps are in the feature docs. → filed: docs/features/wake.md, session.md, discord.md, voice.md, answering.md
- [module] A second review of the fixed code found a regex that froze the bot for over a second, and three fixes that didn't do what the record said (the stop count, the reconnect wait, the intent error). Findings about a library are verified at the code that runs (the throw site, the state changes), and a test is built from the library's real output, not from my reading of it; a new test is checked by breaking its fix. → filed: docs/DEVELOPING.md
